# 0007. API нейросетей через домашний прокси

> Обновлено: 2026-10-17

**Статус**: принято

## Контекст

Поиск по справочнику «по смыслу» и озвучка ИИ ходят в OpenRouter, а он недоступен из России напрямую. У хозяина мира блокировки обходятся на роутере: DNS домашней сети отдаёт для заблокированных доменов адрес своего прокси в локальной сети (192.168.x.x), прокси пропускает TLS дальше. Браузер и другие программы работают, а CC: Tweaked отвечает «Domain not permitted»: правило `$private` запрещает компьютерам частные адреса, и проверяется адрес после DNS.

## Решение

В `config/computercraft-server.toml` (и `defaultconfigs/`) выше запрета `$private` стоят правила `allow` для доменов API нейросетей: `openrouter.ai`, `api.openai.com`, `api.anthropic.com`. Правила CC применяются по порядку, первое подходящее задаёт действие, поэтому эти домены проходят, куда бы их ни направил DNS. Остальные частные адреса закрыты, как раньше. Если обхода нет, DNS отдаёт настоящий адрес и правило ничего не меняет.

## Альтернативы

- **Прокси CC: Tweaked** (`[http.proxy]` + `use_proxy` у правила). Отвергнуто: при пустом адресе прокси запрос с `use_proxy = true` падает с «Proxy host not configured», поэтому «необязательный прокси» потребовал бы переключать правила на лету из KubeJS. Вернуться, если понадобится прокси, который не встаёт в DNS (SOCKS/HTTP на другой машине).
- **Разрешить адрес прокси целиком** (`192.168.0.50`). Отвергнуто: компьютеры в игре получили бы доступ к самому роутеру/прокси.

## Последствия

Новый провайдер нейросети с заблокированным доменом — добавить такое же правило. Доменные правила обходят `$private` только для своих имён.
