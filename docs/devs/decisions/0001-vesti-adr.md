# 0001. Вести записи архитектурных решений (ADR)

> Обновлено: 2026-10-17

**Статус**: принято

## Контекст

Через полгода причины решений забываются: почему ИИ говорит только через экраны; почему корабль ставится кодом, а не командой. `architecture.md` описывает «как сейчас», но не «почему».

## Решение

Каждое значимое решение фиксируется отдельным файлом `NNNN-краткое-имя.md` в этой папке (сквозная нумерация). Формат — как этот файл: Статус / Контекст / Решение / Альтернативы / Последствия. ADR не редактируются задним числом: новое решение получает новый номер, а в старом статус меняется на «заменён ADR-NNNN».

## Альтернативы

- Журнал-секция внутри architecture.md — отклонено: файл разрастается, история мешает читать текущее состояние.
- Не вести — отклонено: контекст решений теряется.

## Последствия

Небольшой оверхед (10–15 строк на решение) в обмен на восстановимую историю. Триггеры создания ADR — в таблице скилла project-docs.
